# Rules

Each file states one decision, why it was taken, how to apply it, the choices it leaves to a
project, and what checks it. Start with [`principles.md`](principles.md). The tables below are
generated by `python template/scripts/docs.py --root . index` from each rule's header; `applies`
says when a rule is relevant.

## Reading paths

- **Scaffolding a new project:** [`principles.md`](principles.md) →
  [`repository/layout.md`](repository/layout.md) →
  [`workflow/documentation.md`](workflow/documentation.md) →
  [`workflow/lines-of-work.md`](workflow/lines-of-work.md) → [`choices.md`](choices.md).
- **Starting a line of work:** [`workflow/lines-of-work.md`](workflow/lines-of-work.md) →
  [`workflow/prespecification.md`](workflow/prespecification.md) →
  [`analysis/code-and-notebooks.md`](analysis/code-and-notebooks.md).
- **Adding a data source:** [`pipeline/sources.md`](pipeline/sources.md) →
  [`pipeline/configuration.md`](pipeline/configuration.md) →
  [`pipeline/verification.md`](pipeline/verification.md).
- **A coding agent's first session:** [`workflow/agent-instructions.md`](workflow/agent-instructions.md)
  → [`workflow/agent-skills.md`](workflow/agent-skills.md)
  → [`workflow/documentation.md`](workflow/documentation.md).
- **Cleaning up:** [`repository/storage-and-hygiene.md`](repository/storage-and-hygiene.md).

## Repository: how any project's repository looks

<!-- docs:begin docs dir=repository columns=summary,applies -->
| Doc | Summary | Applies |
|---|---|---|
| [environment](repository/environment.md) | environment.yml is the input, conda-lock.yml the reproducible lock; repository tools need only the standard library | always |
| [hooks-and-ci](repository/hooks-and-ci.md) | CI runs the docs check, ruff and pytest; opt-in git hooks block notebook outputs, restricted data and inconsistent docs | always |
| [layout](repository/layout.md) | The directory tree: a real package under src/<package>/, notebooks at the top, docs by line of work | always |
| [storage-and-hygiene](repository/storage-and-hygiene.md) | What git tracks and what it doesn't, the data root, scratch, and how to clean up (archive tags, one-off scripts, macOS metadata) | always |
| [testing](repository/testing.md) | tests/ mirrors the package; no __init__.py; test files never import each other; shared setup is fixtures | always |
<!-- docs:end -->

## Pipeline: for projects with a data pipeline

<!-- docs:begin docs dir=pipeline columns=summary,applies -->
| Doc | Summary | Applies |
|---|---|---|
| [cli](pipeline/cli.md) | A console script <package> with verb-first, domain-scoped commands; parser and handlers in separate files; integer exit codes | pipeline projects |
| [configuration](pipeline/configuration.md) | One unified YAML config read once into typed objects; per-machine values in a git-ignored local file | pipeline projects |
| [sources](pipeline/sources.md) | One class per data source with declared steps and prerequisites, a plan/execute split, a lazy registry and one path module | pipeline projects |
| [verification](pipeline/verification.md) | data summary reports completeness from the registry; data verify checks correctness per source; both itemise failures | pipeline projects |
<!-- docs:end -->
