# Environment with pixi (planned)

Proposed replacement for [environment.md](environment.md). Nothing in the template has changed
yet; rendered projects still get `environment.yml` and `conda-lock.yml`. When this is applied,
this rule becomes `current`, `environment.md` is retired, and the changelog says so.

## Decision

- **`pixi.toml`** is the human-edited list of dependencies, the one file to change when adding a
  package: conda-forge packages under `[dependencies]`, PyPI packages under
  `[pypi-dependencies]`, and the project itself as `<package> = { path = ".", editable = true }`.
  It replaces `environment.yml`.
- **`pixi.lock`** is generated by pixi for every platform in `platforms` (`linux-64`, `osx-64`,
  `osx-arm64` by default) and committed. It replaces `conda-lock.yml`. Any `pixi add` or
  `pixi install` updates it; commit it with the change to `pixi.toml`.
- **The environment lives in the project** (`.pixi/`, git-ignored). `pixi run <cmd>` or
  `pixi shell` replace `conda activate`; there is no named, machine-wide environment.
- **Tasks** in `pixi.toml` name the checks once: `pixi run check` runs the docs check, ruff and
  pytest, for people, agents and CI alike.
- **Unchanged:** `pyproject.toml` still carries no dependency list (so the dependencies are in
  `pixi.toml`, not `[tool.pixi]`); repository tools and git hooks stay standard library only.

## Why

The author's machine retired Homebrew and Miniforge on 2026-11-23: Intel macOS 26 has no
Homebrew bottles, and conda environments had drifted from their files (noise-pollution's
environment now lives as a machine-local pixi manifest outside the repository, pointing at one
clone). pixi installs the same conda-forge binaries the geospatial stack needs, resolves PyPI
packages in the same lock, and keeps the environment next to the code, so a worktree or a new
machine gets the locked environment with one `pixi install`. It is one tool instead of conda,
mamba and conda-lock.

## How

Files to change in the template (all render into projects):

- `template/environment.yml.jinja` → `template/pixi.toml.jinja` (Python version from the copier
  answer; geospatial and HPC modules add their packages as now).
- `template/.github/workflows/tests.yml.jinja`: install with `prefix-dev/setup-pixi` (cached on
  `pixi.lock`) and run `pixi run check`.
- `template/AGENTS.md.jinja` and `template/README.md.jinja`: the Environment section and setup
  commands.
- `template/.gitignore`: add `.pixi/`.
- `copier.yml`: questions or help text that mention conda.
- Template docs: this rule, `environment.md` (retire), `hooks-and-ci.md`, `layout.md`,
  `docs/README.md` (generated index), `changelog.md`.

CI already renders two configurations and runs their checks; both must pass with pixi before
merging.

Existing projects, after `copier update`:

- **noise-pollution:** generate `pixi.toml` from its `environment.yml` (`pixi init --import
  environment.yml`, then review), lock, delete `environment.yml` and `conda-lock.yml`, and retire
  `~/.config/pixi-envs/noise_pollution/`. Stata stays outside (`pystata` from StataCorp).
- **growth-and-temperature:** same, after the HPC question below is settled.
